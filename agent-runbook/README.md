# Agent Runbook：AI CLI 项目迁移执行手册

> **你是 AI Agent，且被要求把一批项目从旧目录搬到新目录（可能还要改名）。**
> ⚠️ **命令是 macOS 语法**：`launchctl`、`~/Library/LaunchAgents`、`sed -i ''`（GNU sed 上要**去掉**空引号）。**先按你的平台改写命令再执行**，不要照抄。
> 流程与判断方法跨平台通用，变的只是命令。
>
> **执行流程**自包含——四个阶段照着做即可。只有两种情况需要翻仓库其它文档：
> ① 涉及 ZCode 以外的 AI 工具 → 本仓库不覆盖，请查该工具官方文档
> ② 需要理解某个机制的原理 → [`../docs/binding-mechanisms.md`](../docs/binding-mechanisms.md)
>
> 若你只拿到其中某个 phase 文件，请先读本文件了解全局约束。

---

## 0. 你的任务是什么

把项目迁移后，修复所有"因为路径变了而失效的东西"。典型触发场景：
- 用户说"把这些项目搬到统一目录"；
- 用户说"给这些目录改个可读的名字"。

## 1. 三条铁律（违反可能造成数据损失）

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **不可逆操作前必须备份/留快照** | 数据库、git 未提交改动 |
| 2 | **先做 1 个项目试点，用户验证后，再批量** | 不许一上来就批量改 |
| 3 | **删除一律 `mv` 到 `~/.Trash/`，禁止 `rm`/`rmdir`/`find -delete`** | 即使是空目录、即使用户说"可以删" |

## 2. 三个阶段

| 阶段 | 文件 | 风险 | 是否需要用户配合 |
|---|---|---|---|
| 1 侦察与规划 | `phase-1-inventory.md` | 无（只读） | 否 |
| 2 记忆迁移 | `phase-2-memory.md` | 低（文件层） | 用户验证 |
| 3 会话迁移 | `phase-3-session.md` | 中（改数据库） | **必须让用户退出对应工具** |
| 任意阶段失败 | `rollback.md` | — | — |

## 3. 必须向用户确认的事项（开工前问清楚）

1. **目标路径与命名**：每个项目的最终路径/名字（注意：纯中文名会让记忆前缀退化成 `project`，建议中文+`-英文名`）
2. **哪些不迁**：留守 / 归档 / 测试目录，是否保持原样
3. **服务窗口许可**：是否有正在运行的服务指向这些目录？允许中断多久？
4. **未提交改动**：改动多的仓库，是否先 commit 留快照
5. **删除策略**：确认可删的东西，执行时仍走废纸篓

## 4. 绝对不要做的事

- ❌ 不要修改 AI 工具的**会话内容本体**（rollout/jsonl/历史记录文件）——那不会丢，不用动
- ❌ 不要修改**测试数据、快照文件、注释里的示例路径**——那是功能语义，改了会破坏测试
- ❌ 不要在工具**运行中**修改它的数据库（会锁/损坏）
- ❌ 不要用 `kill` 代替 `launchctl unload`（KeepAlive 会拉回来）
- ❌ 不要手工数 slug 里的横线数（用脚本生成）
- ❌ 不要"顺手"修改本次任务范围外的文件

## 5. 与用户沟通的节奏

- **只读侦察完成后**，先出一份"影响评估报告"，按风险分档（低/中/高），让用户确认再动手；
- 每个阶段完成后，**给出实测证据**（命令 + 数字），不要只说"已完成"；
- 遇到与预期不符的情况（发现额外绑定、盘点错误），**如实汇报并更新评估**，不要硬着头皮继续。

## 附：本文档未覆盖的情况

遇到下列情况，**停下来向用户说明**并请求决策，不要自行发挥：
- 工具的存储结构与 `../docs/binding-mechanisms.md` 描述不符（说明工具升级了，需重新侦察）
- 迁移涉及跨磁盘/跨网络文件系统（inode 行为不同，本手册的结论可能不适用）
- 迁移的是**生产服务器上的服务**而非本地开发环境
